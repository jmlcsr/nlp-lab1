**两个必须在报告中讨论的点：**

1. **类别严重不均衡。** sports 占 75.1%，因此 Accuracy 存在约 **75% 的"地板"** ——
   一个永远输出 sports 的平凡基线就能拿到约 0.75 的 Accuracy（实测见下）。
   这说明**必须同时看 Macro-F1**，也解释了作业为什么要求两个指标都报告。

2. **文本极长，而作业规定 BERT 的 `max_length=64`。**
   实测（`code/analyze.py`，全部 11447 篇）平均 **834.2 个 subword token**
   （中位数 872 / P90 1239 / 最长 6775），远超 64：
   **99.96% 的文档会被截断**，截断后平均只保留 **7.67%** 的 token。
   即 **BERT 只能看到每篇文档开头约 7.7% 的内容**。
   这个参数是作业硬性规定的，必须遵守，但要在报告中量化截断比例并讨论影响。

### 实验 1 / 2：Binary BoW 与 Word Frequency　✅

**命令**

```powershell
cd c:\Users\jmlcsr\Desktop\lab1
& 'D:\Miniconda\envs\lab1\python.exe' code\task1_bow.py --mode binary
& 'D:\Miniconda\envs\lab1\python.exe' code\task1_bow.py --mode freq
& 'D:\Miniconda\envs\lab1\python.exe' code\task1_bow.py --mode binary --class_weight balanced
& 'D:\Miniconda\envs\lab1\python.exe' code\task1_bow.py --mode freq --class_weight balanced
```

**超参数**

| 参数 | 值 |
| --- | --- |
| 词表构建 | **仅用训练集** `fit`，val/test 只 `transform`（避免信息泄漏） |
| `min_df` | 2（丢弃出现次数 < 2 的极低频词） |
| `binary` | True（实验 1/3） / False（实验 2/4） |
| 分类器 | `LogisticRegression(max_iter=1000, C=1.0)` |
| `class_weight` | None（实验 1/2） / `balanced`（实验 3/4） |

**输出要点**

| 项目 | Binary | Frequency |
| --- | --- | --- |
| 词表大小 \|V\| | 53146 | 53146 |
| 非零元素占比（稀疏度 1−density） | 0.5935%（99.41%） | 0.5935%（99.41%） |
| 多数类基线 Acc / Macro-F1 | 0.7511 / 0.2860 | 0.7511 / 0.2860 |
| Val Acc / Macro-F1 | 0.9773 / 0.9436 | 0.9764 / 0.9449 |
| Test Acc / Macro-F1 | **0.9790 / 0.9468** | **0.9825 / 0.9542** |
| balanced 后 Test Macro-F1 | 0.9479（+0.0011） | 0.9506（−0.0036） |

**观察与结论**

1. **两种词袋都极强。** Test Accuracy 0.979~0.983、Macro-F1 0.947~0.954。
   相比多数类基线（Acc 0.7511 / Macro-F1 0.2860），**Macro-F1 提升 +0.66**，
   说明模型真的学到了区分性特征，而不是靠猜多数类。

2. **Word Frequency 略优于 Binary BoW。** Test Macro-F1 **0.9542 vs 0.9468**（+0.0074），
   Acc 0.9825 vs 0.9790（+0.0035）。
   两者维度完全相同（|V| = 53146），唯一差别就是**是否保留词频**，
   故差异可归因于：**词频携带了"强度"信息**（某类新闻的特征词会反复出现）。

3. **`class_weight="balanced"` 几乎没有影响。**
   Binary 0.9468 → 0.9479（+0.0011），Frequency 0.9542 → 0.9506（−0.0036），
   **都在随机波动范围内，没有系统性收益**。
   原因：类别虽然不均衡，但**可分性极强**（sports 的关键词特征非常显著），
   默认 LR 已能把少数类学好；`balanced` 只是把少数类 recall 拉高、precision 拉低，
   Macro-F1 打平。

4. **val 与 test 高度一致**（Binary：0.9436 vs 0.9468），**没有过拟合**；
   test 略好于 val 属于抽样波动。

5. **非零占比极低**：仅 **0.5935%**（稀疏度 99.41%）。9157×53146 ≈ 4.87 亿个格子里
   只有约 289 万个非零，等价于**每篇文档平均只用到约 315 个不同的词**（总词数 637）。
   这是"词表大、每篇用词集中"的直接结果，也是"高维稀疏"的字面含义。
   注：非零占比只是**表示的形态描述，不是评价指标**，没有高低优劣之分。

6. **可复现性已实测验证。** 修改脚本（去掉 sklearn 已忽略的 `n_jobs`）后重跑
   `--mode binary`，输出与修改前**逐位完全一致**（Val 0.9773/0.9436、Test 0.9790/0.9468，
   |V| 与非零占比亦相同）。这说明该实验是**确定性**的 ——
   `CountVectorizer` 无随机成分，`LogisticRegression` 默认 `lbfgs` 求解器无随机初始化。
   **故 Task 1 无需重复实验**（重复跑只会得到完全相同的结果）。

### Task 2 三组横向对比（报告核心）

| 序 | 方法 | 维度 | 词覆盖率 | Test Acc | Test Macro-F1 |
| --- | --- | --- | --- | --- | --- |
| 1 | **GloVe-100**（预训练，60 亿词） | 100 | **98.07%** | 0.9782 | **0.9471** |
| 2 | **W2V(NYT)-100**（自训，同领域） | 100 | 97.58% | 0.9712 | 0.9308 |
| 3 | **W2V(AG News)-100**（自训，跨领域） | 100 | 94.32% | 0.9686 | 0.9227 |

**核心规律：词覆盖率与 Macro-F1 完全同序 —— 覆盖率能完整解释三组的性能排序。**

```
覆盖率：  98.07%  >  97.58%  >  94.32%
Macro-F1：0.9471  >  0.9308  >  0.9227      ← 排序一致
```

机理解释：覆盖率低 → 更多词查不到词向量 → 文档平均向量被"稀释"、判别信息减少。

**与 Task 1 的关系（重要）**：GloVe 以 **100 维**追平了 **53146 维**的 Binary BoW
（0.9471 vs 0.9468，差 0.0003），即约 **500 倍维度压缩且无性能损失**；
说明词向量平均在**高维稀疏 → 低维稠密**的转换上是成功的，
但未能超越词频词袋（差 0.0071）。这与数据集"文本长、类别可分性强"的特点有关。

### 实验 8：BERT-base-uncased 微调　✅ **Macro-F1 最佳**

```powershell
# 正式实验：3 epochs。重复运行 4 次以获得均值与波动（最终指标见 results/results.json）
& 'D:\Miniconda\envs\lab1\python.exe' code\task3_bert.py --no_save --out models/bert-base-uncased-len64-ep3
```

**超参数**

| 参数 | 值 |
| --- | --- |
| 预训练模型 | `google-bert/bert-base-uncased` |
| max_length | **64**（作业硬性要求） |
| epochs | **3**（作业硬性要求） |
| learning_rate | 2e-5 |
| batch_size | 16（train） / 32（eval） |
| weight_decay | 0.01 |
| 精度 | bf16（RTX 4060 支持 bf16） |
| seed | 42 |
| 保存策略 | `--no_save`（不存 checkpoint、不回载，使"训练 3 epochs"严格对应末轮模型） |

**结果（4 次独立运行）**

| 项目 | 值 |
| --- | --- |
| 训练步数 | 1719（9157 / 16 × 3） |
| 训练耗时 | 133.7 ~ 219.8 秒（约 2.2 ~ 3.7 分钟，随 GPU 功耗状态浮动） |
| train_loss（末轮） | 0.062 ~ 0.067 |
| Val Macro-F1（均值） | 0.9473 |
| **Test Acc（均值 ± 标准差）** | **0.9832 ± 0.0013** |
| **Test Macro-F1（均值 ± 标准差）** | **0.9597 ± 0.0033** |
| 各次 Test Macro-F1 | 0.9630 / 0.9558 / 0.9620 / 0.9582（范围 0.9558 ~ 0.9630） |

**观察**

1. **BERT 的 4 次运行都优于最强的词袋（Word Frequency，0.9542）**，
   平均高 **Macro-F1 +0.0055**；但 **Accuracy 基本持平**（0.9832 vs 0.9825），
   其中一次运行（0.9817）甚至低于词袋。
   **即"BERT 更好"仅体现在 Macro-F1 上，且幅度很小**，不能表述为"显著优于"。

2. **`max_length=64` 只覆盖全文约 7.7%（实测），但 BERT 依然拿到了最优的 Macro-F1。**

   | 截断统计（`code/analyze.py`，11447 篇） | 值 |
   | --- | --- |
   | 平均 / 中位数 / P90 / 最长 token 数 | 834.2 / 872 / 1239 / 6775 |
   | 被截断的文档占比 | **99.96%** |
   | 平均保留 token 比例 | **7.67%** |

   原因：这 64 个 token 对应的是**标题 + 导语**，而新闻导语恰恰是主题信息最密集的部分。
   这说明"截断"不等于"丢信息"，**关键看截掉了什么**；
   不过截断同时也限制了它拉开差距的空间 —— BERT 用 7.7% 的内容只换来对"用满 100% 词汇"的词袋的微弱优势。

3. **轮间波动明显**（如第 1 次运行：0.9463 / 0.9346 / 0.9512），说明微调过程存在随机性；
   4 次运行的末轮都接近各自最优，但**不能假设末轮总是最优**。

4. **训练中的非单调点**：epoch 1 → 2 之间 Val Macro-F1 时常不升反降
   （0.9463 → 0.9346、0.9488 → 0.9384），与学习率在 warmup 之后逐步衰减的过程相符。

**多次运行与可复现性（重要）　✅**

**问题**：同一配置（`seed` 固定为 42）、同一数据划分，重复运行得到的指标并不相同。

| 次 | Val Macro-F1（ep1 / ep2 / ep3） | Test Acc | Test Macro-F1 |
| --- | --- | --- | --- |
| 1 | 0.9463 / 0.9346 / 0.9512 | 0.9843 | 0.9630 |
| 2 | 0.9436 / 0.9440 / 0.9494 | 0.9817 | 0.9558 |
| 3 | 0.9401 / 0.9307 / 0.9455 | 0.9843 | 0.9620 |
| 4 | 0.9488 / 0.9384 / 0.9431 | 0.9825 | 0.9582 |
| **均值 ± 标准差** | — | **0.9832 ± 0.0013** | **0.9597 ± 0.0033** |

**证据**：第 1 次与第 2 次运行在**第 50 步**的 `train_loss` 就已经不同（0.5087 vs 0.5369）。
而第 50 步之前两次运行都**没有写过任何 checkpoint**，
故该差异**不是** checkpoint 保存/回载造成的。

**原因**：训练在 GPU 上进行，存在非确定性 kernel ——
`nn.Embedding` 的反向传播用 `atomicAdd` 把梯度累加到同一个词向量上（浮点加法顺序不定）、
`scaled_dot_product_attention` 的反向 kernel、以及 bf16 下的归约顺序。
`seed=42` 只能固定**参数初始化**与**数据顺序**，无法约束这些 kernel 的执行顺序。

**处理**：

- 报告 BERT 时给出**均值 ± 标准差**，而不是单次值；
- 结论按"与最强词袋基线相当或略有优势"表述，**不下"显著优于"的强结论**；
- 反证对照：Task 1（`CountVectorizer` + `lbfgs`）已实测重跑**逐位一致**（确定性）；
  Task 2 的 gensim `Word2Vec` 在固定 `seed=42` 后亦稳定。
  即**不确定性只出现在 GPU 上的 BERT 微调**。

## 4. transformers 5.19 环境注意事项（复现要点）

本机使用的是较新的 `transformers 5.19.0`，有几点与旧版不同，脚本中已做兼容：

| 现象 | 说明与处理 |
| --- | --- |
| `evaluation_strategy` 参数不存在 | 4.46 起改名为 `eval_strategy`，脚本用 `inspect.signature` 自动选名 |
| `warmup_ratio` 不被支持 | 脚本会自动过滤并打印 `[warn] ... 已忽略: ['warmup_ratio']`；实际无 warmup |
| `save_pretrained → load_state_dict` 往返中 LayerNorm 键不匹配 | 保存为 `gamma`/`beta`、加载时期望 `weight`/`bias`，会打印大量 missing/unexpected 警告。**已实测确认不影响最终结果**（回载前后 Val 指标逐位一致：0.9782 / 0.9512）；正式实验改用 `--no_save` 后该路径不再触发 |
| （已澄清的误判）曾以为 `save_strategy="no"` 会触发 collator 异常 | 报错 `TypeError: vars() argument must have __dict__ attribute`（或自定义 collator 下的 `'TextClfDataset' object has no attribute 'keys'`）**实为本脚本自身的 bug**：`ds_train = TextClfDataset(...), args.no_save` 多写了一个逗号，使 `train_dataset` 变成 **tuple**，`collate_fn` 因此收到 `[Dataset]`。**修正后 `--no_save` 稳定运行 3 次** |

**结论**：正式实验使用 `--no_save`（`save_strategy="no"`、不回载），
既规避了 LayerNorm 往返的警告噪声，又使"训练 3 epochs"严格对应**末轮模型**；
该配置已稳定运行 3 次。**BERT 的最终指标是 4 次独立运行的均值 ± 标准差**（见实验 8）。

## 6. 综合分析（对应报告第 5 章）

### 6.1 从词袋到词向量再到预训练模型

| 表示 | 维度 | 最好的 Test Macro-F1 | 相对词袋 |
| --- | --- | --- | --- |
| Bag of Words（词频） | 53146 | 0.9542 | 基准 |
| 预训练词向量平均（GloVe） | 100 | 0.9471 | −0.0071 |
| 自训练词向量平均（NYT） | 100 | 0.9308 | −0.0234 |
| **预训练语言模型微调（BERT）** | **768** | **0.9597**（4 次运行均值） | **+0.0055** |

**三层结论：**

1. **词袋在这个数据集上异常强**（0.9542）。原因是文本极长（平均 637 词），
   词袋能**无损保留全部词汇信息**；而"平均词向量"把 637 词压成 100 维，信息损失巨大。
   这与"词向量必然优于词袋"的常见直觉相反，是**长文本 + 类别可分性强**这一数据特点造成的。
2. **词向量的价值体现在"压缩比"而非"绝对性能"**：100 维追平 53146 维，
   维度降低约 500 倍而性能基本不变 —— 这才是词向量的核心贡献。
3. **端到端的预训练模型微调确实超过了词袋，但优势很有限**（Macro-F1 +0.0055，
   约为运行波动 0.0033 的 1.7 倍），靠的是**上下文相关表示**
   （平均词向量丢失语序，"狗咬人"与"人咬狗"不可区分）。
   在**长文本 + 类别可分性强**的数据上，词袋本身就是极强的基线，
   加上 BERT 被硬性限制在 64 token，它很难拉开差距。

### 6.2 类别不均衡的影响

- 多数类基线：**Acc 0.7511 / Macro-F1 0.2860** —— Accuracy 存在 75% 的地板。
- 但所有方法（含最简单的词袋）的 Macro-F1 都远超 0.93，
  `class_weight="balanced"` 反而**没有收益**（+0.0011 / −0.0036）。
- **结论**：本数据集虽然类别不均衡，但**类别可分性极强**，
  不均衡并未实际阻碍学习；报告 Accuracy 时**必须同时给出多数类基线**才有意义。

### 6.3 错误分析　✅

数据来源：`results/bert_test_predictions.csv`（第 4 次运行的预测，Acc 0.9825，与 results.json 一致）；
脚本 `code/analyze.py`，明细见 `results/error_analysis.md`。

**混淆矩阵（行 = 真实，列 = 预测）**

| 真实 \ 预测 | business | politics | sports | 合计 | 错分率 |
| --- | --- | --- | --- | --- | --- |
| **business** | 129 | 11 | 2 | 142 | **9.15%** |
| **politics** | 4 | 139 | 0 | 143 | 2.80% |
| **sports** | 0 | 3 | 857 | 860 | **0.35%** |

**错误共 20 / 1145（1.75%）**，且分布高度集中：

| 真实 → 预测 | 次数 | 占全部错误 |
| --- | --- | --- |
| **business → politics** | 11 | 55% |
| politics → business | 4 | 20% |
| sports → politics | 3 | 15% |
| business → sports | 2 | 10% |

**结论**

1. **错误集中在 business ↔ politics（15 / 20 = 75%）**，与预判一致：
   两类都是"社会经济 / 公共事务"题材，边界天然模糊
   （典型错例："密苏里州商会游说州议会扩大医保"—— 商业团体在做政治游说）。
2. **sports 几乎不会错**（错分率 0.35%，3 / 860）：该类判别特征极强，
   也是它撑起 0.98 Accuracy 的原因。
3. **错误方向不对称**：business → politics 有 11 次，反向仅 4 次 ——
   business 报道常涉及政策与政府，更容易被"政治化"。
4. **存在标注噪声的可能**：错例中有"布什政府与美联储主席伯南克"
   "16 天政府停摆的成本"等本身横跨政治与经济的报道，人工标注也有争议空间。
5. **Accuracy 的钝感**：sports 占 75.1%，即使把 13 个 business 错例全部修正，
   Accuracy 也只提升约 0.011 —— 再次说明该数据集上 **Macro-F1 比 Accuracy 更有区分度**。
