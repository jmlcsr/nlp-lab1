**两个必须在报告中讨论的点：**

1. **类别严重不均衡。** sports 占 75.1%，因此 Accuracy 存在约 **75% 的"地板"** ——

2. **文本极长，而作业规定 BERT 的 `max_length=64`。**
   平均 637 词（转成 subword token 通常 800+）远超 64，
   意味着 **BERT 只能看到每篇文档开头约 8% 的内容**。
   这个参数是作业硬性规定的，必须遵守，但要在报告中量化截断比例并讨论影响。

## 3. 各组实验详情

### 实验 1 / 2：Binary BoW 与 Word Frequency　✅ 已完成

**命令**

```powershell
cd c:\Users\jmlcsr\Desktop\lab1
& 'D:\Miniconda\envs\lab1\python.exe' code\task1_bow.py --mode binary
& 'D:\Miniconda\envs\lab1\python.exe' code\task1_bow.py --mode freq
& 'D:\Miniconda\envs\lab1\python.exe' code\task1_bow.py --mode binary --class_weight balanced
& 'D:\Miniconda\envs\lab1\python.exe' code\task1_bow.py --mode freq --class_weight balanced
```

**超参数**

| 参数 | 值 |
| --- | --- |
| 词表构建 | **仅用训练集** `fit`，val/test 只 `transform`（避免信息泄漏） |
| `min_df` | 2（丢弃出现次数 < 2 的极低频词） |
| `binary` | True（实验 1/3） / False（实验 2/4） |
| 分类器 | `LogisticRegression(max_iter=1000, C=1.0)` |
| `class_weight` | None（实验 1/2） / `balanced`（实验 3/4） |

**输出要点**

| 项目 | Binary | Frequency |
| --- | --- | --- |
| 词表大小 \|V\| | 53146 | 53146 |
| 矩阵稀疏度（非零占比） | 0.5935% | 0.5935% |
| 多数类基线 Acc / Macro-F1 | 0.7511 / 0.2860 | 0.7511 / 0.2860 |
| Val Acc / Macro-F1 | 0.9773 / 0.9436 | 0.9764 / 0.9449 |
| Test Acc / Macro-F1 | **0.9790 / 0.9468** | **0.9825 / 0.9542** |
| balanced 后 Test Macro-F1 | 0.9479（+0.0011） | 0.9506（−0.0036） |

**观察与结论**

1. **两种词袋都极强。** Test Accuracy 0.979~0.983、Macro-F1 0.947~0.954。
   相比多数类基线（Acc 0.7511 / Macro-F1 0.2860），**Macro-F1 提升 +0.66**，
   说明模型真的学到了区分性特征，而不是靠猜多数类。

2. **Word Frequency 略优于 Binary Bo✅ 已完成。** Test Macro-F1 **0.9542 vs 0.9468**（+0.0074），
   Acc 0.9825 vs 0.9790（+0.0035）。
   两者维度完全相同（|V| = 53146），唯一差别就是**是否保留词频**，
   所以差异可归因于：**词频携带了"强度"信息**（某类新闻的特征词会反复出现）。

3. **`class_weight="balanced"` 几乎没有影响。**
   Binary 0.9468 → 0.9479（+0.0011），Frequency 0.9542 → 0.9506（−0.0036），
   **都在随机波动范围内，没有系统性收益**。
   原因：类别虽然不均衡，但**可分性极强**（sports 的关键词特征非常显著），
   默认 LR 已能把少数类学好；`balanced` 只是把少数类 recall 拉高、precision 拉低，
   Macro-F1 打平。

4. **val 与 test 高度一致**（Binary：0.9436 vs 0.9468），**没有过拟合**；
   test 略好于 val 属于抽样波动。

5. **稀疏度极低**：非零元素仅 **0.5935%**。9157×53146 的矩阵里约 99.4% 是 0，
   直观体现了词袋表示的**高维稀疏**本质。

> **一个需要提前预警的推论：** 本数据集平均文本 **637 词**，信息量很大，
> 而词袋恰好能把长文本的全部词汇信息保留下来，所以表现很强。
> Task 2 的"词向量平均"会把整篇文档压缩到 **100 维**，信息损失远大于词袋，
> 因此 **Task 2 未必能超过 Task 1**。这与"词向量一定优于词袋"的直觉相反，
> 但在长文本场景下是合理的 —— 等 Task 2 结果出来验证。

#### 2026-10-07 下载排查记录（四种方式均未成功）

| # | 方式 | 结果 |
| --- | --- | --- |
| 1 | `curl` **直连** `http://nlp.stanford.edu/...` | 能连上（拿到 308 重定向 + 822 MB 文件头），但限速 **12 KB/s → ETA 19 小时** |
| 2 | `curl -x http://127.0.0.1:7897`（走代理） | **0 字节**，生成空文件 → `zipfile.BadZipFile` |
| 3 | Python urllib + 系统代理，`http://` | **HTTPError 502 Bad Gateway**（502 由代理返回） |
| 4 | Python urllib + 系统代理，`https://` | **SSLEOFError: UNEXPECTED_EOF_WHILE_READING**（TLS 握手阶段被中断） |

#### 结论与线索

- 同一代理访问 `pypi.org` / `download.pytorch.org` / `github.com`（**均 HTTPS**）
  **全部正常，5~7 MB/s** → 代理本身可用。
- 但访问 `pypi.tuna.tsinghua.edu.cn` 时也报过**同一个 `SSLEOFError`**。
- **不走代理**时 Stanford 反而能建立连接并开始传输 → 说明不是"境外站点被掐"，
  而是**该代理节点到 Stanford 的线路不通**。
- 综合：直连太慢、代理不通，**结论是必须换源（镜像）**。

#### ✅ 解决方案（2026-10-08 已解决）

**做法：换用 HuggingFace 镜像站的现成 `glove.6B.100d.txt`，并保留系统代理。**

```powershell
cd c:\Users\jmlcsr\Desktop\lab1
& 'D:\Miniconda\envs\lab1\python.exe' code\download_glove.py --mirror
```

**镜像来源**（先核对文件大小才使用）：
`https://hf-mirror.com/datasets/dodekVanBurak/glove6B100d/resolve/main/glove.6B.100d.txt`

- 大小 **347,117,594 字节**，与官方 `glove.6B.100d.txt` **逐字节一致**
- 仓库 public、未设门禁；直接下 `.txt`，省去下载 822 MB zip 再解压的步骤
- 结果：`embeddings\glove.6B.100d.txt`，331.0 MiB，耗时约 1 分钟，平均 ~5.3 MB/s

**关键经验（三条，都是踩坑换来的）**

| # | 结论 |
| --- | --- |
| 1 | **必须走代理。** 该链接会 302 跳到 `https://us.aws.cdn.hf.co/xet-bridge-us/...`（HuggingFace 的 Xet 存储节点，**境外域名**）。直连时本地 DNS 解析不出它（`getaddrinfo failed`）；走代理则由**代理端**解析，畅通。 |
| 2 | `--no_proxy` 在这里是**反效果**：入口域名 `hf-mirror.com` 国内可达，但**落地 CDN 在境外**，绕过代理等于掐断 DNS。 |
| 3 | **换源前必须先核对文件大小。** 同样搜到的 `SLU-CSCI4750/glove.6B.100d.txt` 只有 134 MB，是裁剪版，用了结果就是错的。 |

> **纠错备忘**：清空 `HTTP_PROXY` / `HTTPS_PROXY` 环境变量**无法**绕过 Windows 系统代理 ——
> `urllib.request.getproxies()` 的逻辑是"环境变量优先，**为空则回落到注册表**"。
> 要在代码里真正绕过，需 `build_opener(ProxyHandler({}))`，或在
> Windows 设置 → 网络和 Internet → 代理 里关闭"手动设置代理"。
